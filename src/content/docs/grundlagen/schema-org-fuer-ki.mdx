> **Kurzfassung:** Schema.org beschreibt in strukturierten Daten, wer hinter einer Website steht und was sie anbietet. Für Antworten von ChatGPT, Perplexity oder Google AI Overviews ist es nach heutigem Stand nicht nötig. Nützlich bleibt es für Rich Results in der Google-Suche und um Angaben zu dir eindeutig festzuhalten.

## Das Wichtigste in 30 Sekunden

- Schema.org = strukturierte Daten im JSON-LD-Format, meist im HTML-Head
- Google sagt: Für KI-Antworten braucht es kein Schema.org-Markup
- Messungen zeigen keinen Zugewinn an KI-Zitaten durch JSON-LD
- Nützlich bleibt es für Rich Results in der Google-Suche
- Wichtigste Typen: Person, Organization, Service

Menschen lesen deine Texte und verstehen sie. Maschinen brauchen strukturierte Daten.

Schema.org ist ein standardisiertes Vokabular das sagt:
- "Das ist eine Person"
- "Das ist ihr Beruf"
- "Das sind ihre Angebote"
- "Das ist ihr Standort"

## Was Schema.org für KI-Antworten bringt

Lange galt Schema.org als Pflicht für KI-Sichtbarkeit. Auch auf dieser Seite stand das so. Die Belege sehen inzwischen anders aus:

- Google schreibt in seinem Leitfaden, strukturierte Daten seien für die generative KI-Suche nicht erforderlich und es gebe kein spezielles Markup dafür ([Google](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)).
- Bing sagt, strukturierte Daten können die Zuordnung erleichtern, garantieren aber keine Sichtbarkeit ([Bing](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a)).
- Ahrefs hat 1.885 Seiten untersucht, die JSON-LD neu eingebaut haben. Bei ChatGPT und Googles AI Mode gab es keinen messbaren Zugewinn ([Ahrefs](https://ahrefs.com/blog/schema-ai-citations/)).

Sprachmodelle lesen deinen sichtbaren Text. Steht dort klar, wer du bist und was du anbietest, reicht das. Die Herleitung mit allen Quellen steht in [LLM-Optimierung: Was in KI-Antworten nachweislich hilft](https://codeback.de/llm-optimierung/).

Wofür sich Schema.org trotzdem lohnt: Google zeigt damit Rich Results an, etwa Sterne oder Preise. Und du hältst deine Angaben einmal maschinenlesbar fest. Wenn du das willst, zeigt der Rest dieser Seite, wie es geht.

## Wo kommt der Code hin?

```html
<!DOCTYPE html>
<html>
<head>
  <title>Maria Müller - Business Coach</title>
  
  <!-- Schema.org JSON-LD hier einfügen -->
  <script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "Person",
    "name": "Maria Müller",
    ...
  }
  </script>
  
</head>
<body>
  ...
</body>
</html>
```

## Typische Fehler

<Aside type="danger" title="Zu wenig Informationen">
```json
// Schlecht
{ "@type": "Person", "name": "Maria" }

// Gut
{ "@type": "Person", 
  "name": "Maria Müller",
  "jobTitle": "Business Coach",
  "address": {...}
}
```
</Aside>

<Aside type="danger" title="Falscher Typ">
```json
// Schlecht - Organization für Einzelperson
{ "@type": "Organization", "name": "Maria Müller" }

// Gut
{ "@type": "Person", "name": "Maria Müller" }
```
</Aside>

<Aside type="caution" title="Nicht im Head">
Schema.org muss im `<head>` sein, nicht irgendwo im Body versteckt.
</Aside>

## Häufige Fragen

### Brauche ich alle Schema-Typen?

Nein. Starte mit dem wichtigsten (Person oder Organization). Füge später Service und FAQPage hinzu.

### Schadet falsches Schema meinem Ranking?

Bei Google: möglicherweise. Bei Sprachmodellen spielt das Markup nach heutigem Stand kaum eine Rolle, sie lesen vor allem den sichtbaren Text. Falsche Angaben helfen trotzdem niemandem. Lieber weniger, dafür korrekt.

### Kann ich Schema.org ohne Programmierkenntnisse einbauen?

Ja. Mit WordPress-Plugins ist es klickbar. Für andere Systeme brauchst du Zugang zum HTML-Head.

### Wie oft muss ich Schema.org aktualisieren?

Bei Änderungen an den Fakten (neuer Standort, neue Angebote). Nicht ständig nötig.
